# Project context

This file belongs to the project. Initialization creates it once; template
upgrades preserve it. Keep it concise and edit it as the work develops.

## Purpose and current direction

Use the owner's current request to determine the objective, scope, and useful
deliverable. Preserve consequential choices and remaining questions in project
Memory when they will help later work. Add a standing project purpose here when
one has been established.

## Working preferences

Use native development and scientific tools. Choose direct work or delegation
according to the task. Retain useful code, capabilities, data descriptions, and
interpretations without making every temporary action a managed object.

## Machines and resources

Resolve host paths through `.accrete/local.toml` and domain Tool instructions.
Place current machine restrictions, resource allocations, and environment
conventions here when they are relevant. The template imposes no GPU assignment,
worker count, model family, interpreter, or scientific package version.

## Retention and continuation

Keep the material needed to continue useful work. Prefer referring to existing
Results and Memory over repeating an activity merely to reconfirm it. Describe
changed assumptions explicitly. Before removing a temporary worktree or run
directory, retain the selected products that future work will use.
