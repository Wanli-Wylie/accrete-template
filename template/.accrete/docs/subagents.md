# Working as an ACCRETE subagent

Work on the delegated question using the host's normal tools. Your useful
contribution may be code, a diagnostic, a reduction, a capability, an explanation,
or a concrete unresolved observation. ACCRETE provides a way to retain selected
products; it does not prescribe how to investigate the question.

## Reconstruct the necessary context

Identify the owning ACCRETE project and the actual editable checkout or path.
Read the instructions relevant to that location and the supplied Tool Skill.
If you start outside the project root, read its `AGENTS.md` and
`.accrete/PROJECT.md` explicitly; discovery in another Git repository may expose
a different instruction set.

Use the designated Model revision and environment when the assignment names
them. A shell working directory, Git HEAD, and an installed Python package can
point to different implementations. When execution identity matters, obtain it
from the domain launcher or actual runtime context. Keep an unavailable historical
revision unknown instead of substituting today's HEAD.

Search the relevant Memory rather than loading every entry. Use retained work
under its stated conditions. No general rule requires repeating earlier work
before you can use it.

## Work within the assigned context

Keep overlapping edits in your assigned worktree or disjoint directory. Do not
switch a shared checkout's branch while another worker is using it. Read-only
input data can remain shared. Follow the current resource allocation and make
new resource needs visible to the Coordinator when they affect other work.

Use native Git, editors, scientific libraries, shell, SSH, and schedulers for
the substantive task. Temporary scripts and observations may remain in Scratch.
Do not promote every helper to a Tool or every intermediate array to Data.
Retain them when there is a continuing purpose.

An ACCRETE iteration belongs to the actual Model repository. A worktree supplied
by the agent host may instead isolate the project repository. Use the explicit
Model binding and paths in the brief; do not infer they are equivalent.

## Publish when it is part of the assignment

Use `accrete` to publish managed objects. Draft structured input or Memory
prose in an ordinary working file, then submit it. You can record useful failed
or partial activity, retain external references, and admit work retrospectively.
Missing local payloads do not require fabricating a completed computation.

Keep the command's returned object IDs, revisions, paths, and any pending effects
in the handover. If only indexing remains, the object has already committed.
If a transfer, worktree or publication stopped partway, run `accrete recover` and
report what it finished. If an amendment conflicts with another writer, retain your
draft and reconcile the specific changes with the current document or Coordinator.

Do not edit shared managed descriptors or SQLite directly. On a host without the
binary, continue native work and hand over the prepared draft with the specific
command it needs.

## Return a useful handover

Explain what happened and where the concrete material is. Include the actual
revisions, result/data IDs, relevant observations, and remaining questions that
matter to integration. Describe important behavior changes in a Tool so the next
action can load the updated source; a refresh of files does not erase already
loaded instructions from another session.

A handover can be a few sentences. For example:

> The reduction program is committed on the assigned branch at the revision
> below. It reads the completed first-year output without changing that tree.
> The reduced table is at the named remote path and its Data ID is attached.
> The second year's input is still being produced, so only the first year's
> observations are described in the Result. I left the draft interpretation
> beside the table for integration with the comparison worker's findings.

Fill the concrete references from your work. Do not create a task card or
administrative report merely to fit this example. Before removing a temporary
worktree, return or retain the selected source and products needed later.
