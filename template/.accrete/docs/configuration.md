# Project configuration and host bindings

Shared configuration describes the project. Local configuration binds that
description to this host. Native tools retain their own environments,
credentials, and settings. The Kernel resolves these inputs when an invocation
needs them; reading configuration does not execute shell code or activate an
environment.

## Configuration ownership

| File or layer | Intended contents | Handling |
|---|---|---|
| `.accrete/project.toml` | Project ID, format, timezone, logical roots, named locations and environment labels | Generated by native initialization, then shared with project documents |
| `.accrete/local.toml` | Host alias, absolute checkouts, local state base, storage roots, interpreter/tool paths | Ordinary owner-edited ignored file on each host |
| Invocation arguments | Owning project, a one-time destination or supported option | Applies to that command only |
| SSH, rclone, environment manager, scheduler configuration | Their native access and runtime arrangements | Managed by those tools |

The source template carries examples, not initialized project identities. Native
`accrete init` creates the actual project marker and configuration. Do not copy an
example's identity over an existing project or run initialization separately in
each clone to obtain the same project. A clone carries the shared project ID and
receives its own host bindings.

Precedence is invocation arguments, local overrides, shared values, then
distribution defaults. Lists replace earlier lists. Maps merge by explicit key;
endpoint definitions must follow the CLI's documented replacement semantics
rather than accidentally mixing unrelated access settings.

## Resolve the project explicitly when needed

The expected discovery order is explicit `--project PATH`, `ACCRETE_PROJECT`,
then the nearest marker in the current directory's ancestors. The CLI contract
documents the concrete interface. No global inventory chooses a project on
your behalf.

Use `--project` when working from a Model repository, Tool directory, or run
directory outside the project. This selects the owning metadata without
relocating or redefining that Model or Tool. Relative configured paths resolve
against the selected project root, independently of the shell's working
directory. Use quoted path arguments when paths contain spaces.

## Defaults and examples

| Configuration purpose | Relative default |
|---|---|
| Object descriptors | `.accrete/objects` |
| Results | `results` |
| Dated Memory | `memory` |
| Editable Tool sources | `tools` |
| Ongoing Scratch | `scratch` |

Read the examples under `.accrete/config-examples/` for a shared configuration,
a workstation binding, and a compute-host binding. They illustrate the
architecture's table structure. The installed CLI's configuration schema and
resolver decide supported fields; `.accrete/docs/cli-contract.md` declares the
template's compatibility expectations and `.accrete/docs/cli-commands.md`
describes its expected commands. Keep actual Model aliases and location names
aligned with the project's registered objects.

Choose the project timezone deliberately because it selects future Memory date
directories. It is independent of the host's clock display and of scientific
simulation time. Historical imported dates remain as authored.

## Local operation state

The local state base holds this host's locks, SQLite projections, and incomplete
operation receipts. The Kernel partitions it by the project ID and canonical
managed metadata roots. Different branch worktrees have different metadata
views even when their Git object database is shared.

Select a host-local filesystem for this state. A home directory or project root
on NFS/Lustre is not automatically a suitable place for a live SQLite WAL
database. Several hosts must not use one index as a shared database. Use a
selected host for writes to a shared metadata view, or separate checkouts that
exchange portable documents.

The projection is disposable and can be rebuilt. An incomplete-operation receipt
may still explain a surviving worktree or transferred payload, so do not treat
all local state as a cache to delete indiscriminately. Read the concrete outcome
and recovery instructions before cleaning it up.

## Model and environment bindings

A Model identity can point to a checkout on this host through an alias such as
`target`; that alias is project-defined. The model can be the project repository,
an external repository, an optional submodule, or a worktree. Use native Git to
obtain it and the Kernel's binding operation to associate the known Model with
the actual checkout.

An environment label carries instructions and host paths for the capability that
uses it. One Model revision can run in several environments. The Kernel does not
create a Python environment or install scientific dependencies because a binding
or branch changed. Domain Tools manage language-specific setup and describe the
runtime actually used in a Result when useful.

Place current machine restrictions in `.accrete/PROJECT.md` or the relevant Tool
reference. A configured GPU preference or scheduler name is informative; it does
not reserve hardware across projects.

## Changes and missing bindings

Configuration is normal editable TOML. Use supported TOML 1.0 syntax and plain
paths. Shell expressions in values remain data. Use environment expansion only
where the installed CLI explicitly supports it, with its undefined-variable
behavior understood.

If a checkout or source is absent, retain the shared object identity and repair
that host's binding. Do not retire the object or substitute an unrelated path.
An unavailable remote locator can remain useful historical context. A Result
received from another host may contain references that are intentionally
unresolved locally.

Use the expected configuration-resolution diagnostic,
`accrete --project PATH config resolve --json`, to inspect effective roots before
a managed write when placement is uncertain. Check the installed binary's help
for its available interface. Read descriptors, code, and scientific data with
their native tools after resolution.
